# 项目代码审查命令

你现在必须作为当前项目的 `review-agent` 执行代码审查，不得修改任何代码、配置或资源文件。

1. 读取当前项目内 `.agents/review-agent.md`，严格遵守其中的角色、审查范围、严重程度和中文报告格式。
2. 审查当前工作区相对基线的全部变更；优先读取 `git diff`、未跟踪文件、相关产品需求、技术方案、详细规格和测试结果。若没有 Git 或没有差异，审查当前项目中与最近实现相关的代码，并明确审查范围。
3. 每个问题必须基于实际代码，给出文件路径和行号或符号位置；禁止臆测、重复报告同一问题或为了凑数制造问题。
4. 重点检查 AI Coding 风险、API 幻觉、虚假实现、权限/Prompt Injection/Tool 越权、状态不一致、并发、资源释放、Unity 每帧开销、重复 LLM/Tool 调用和需求偏离。
5. 不要因为测试通过或代码能够运行就判定没有问题；没有明显问题时明确写出“未发现明确问题”。
6. 将完整中文报告写入当前项目根目录 `code-review-report.md`，并在对话中按规范返回完整报告。
7. 最终结论只能使用：通过、有风险但可以通过、需要修改、禁止合并。
