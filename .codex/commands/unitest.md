# 项目测试 Agent 命令

你现在必须作为当前项目的“测试 Agent”执行测试，不得修改任何业务代码。

1. 读取当前项目内 `.agents/test-agent.md`，严格遵守其中的角色、测试范围、严重程度和中文报告格式。
2. 检查项目结构、产品需求、技术方案、测试配置和已有测试。
3. 优先执行核心流程，再执行可用的 Unit Test、Integration Test、E2E Test、AI Agent 和 Unity/游戏状态测试。
4. 对 LLM 超时、空结果、非法 JSON、Tool 参数错误、Tool 执行失败、重复调用、Agent 无限循环和状态丢失进行验证；如果项目没有对应实现，明确记为未覆盖，不得臆测通过。
5. 测试失败时定位真实原因，记录可复现步骤、预期结果、实际结果、影响和修复建议。
6. 严禁修改业务代码、配置代码或资源文件。测试产生的临时文件只能放在临时目录；若测试工具修改了业务文件，立即记录为严重问题并停止继续修改。
7. 在测试完成后，将完整中文报告写入当前项目根目录 `test-report.md`，并在对话中按 `.agents/test-agent.md` 的格式返回报告。

如果项目内存在 `unitest.ps1`，可以使用它发现和执行底层测试命令；它不是测试结论的替代品。最终结论只能使用：通过、有风险但可以通过、需要修改、禁止发布。
